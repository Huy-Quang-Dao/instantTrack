How it works

SuperMimic's loop,
rebuilt for the GPU.

InstantTrack keeps SuperMimic's algorithm. One differentiable world model learns the dynamics, and the policy is trained by backpropagating the imagined return through it. The blue tags mark what InstantTrack changes in each step.

--fused_rot

Fused 3×3 rotations

The rotation products in kinematics, reward, observation and world model are written element-wise, so torch.compile fuses them. They no longer go to cuBLAS as about 57 ms of batched GEMVs per iteration.

+14%iterations per second

--compile_more

Compile the whole step

Reward, termination, observation, goal and normalizer inputs are compiled too. Each iteration drops from 25.3k to 15.2k kernel launches.

315 → 209 msper iteration, under the profiler

--wm_hidden 1024,1024,1024

A right-sized world model

For 40 clips, a 1024³ world model learns as much per iteration as the paper's 2048³, and each iteration is much cheaper.

+28%iterations per second

--pi_ema 0.995

EMA policy

The checkpoint is a Polyak average of the policy weights. That alone takes SuperMimic from 1.50 h to 0.55 h, so we count it as part of the baseline.

2.7×on SuperMimic alone

--fail_reset 0.3

Failure-focused resets

A per-second termination rate tracks where episodes fail, and 30% of resets start one second before those points. Hard clips such as fall-and-get-up are no longer forgotten between checkpoints.

0.27 → 0.22 hmean time to target

--contact_reward 0.25

Contact reward, imagination only

A differentiable foot-contact indicator is matched to the reference, and foot sliding is penalized while the reference foot is down. Evaluation uses SuperMimic's reward unchanged.

0.74 → 0.81foot-contact agreement

Questions.

Is this the official SuperMimic code?

No. No official SuperMimic code is released. Our SuperMimic is the mjlab port of supermimic_vibed, an independent reimplementation of the paper. The paper reports ~1.2 h to return 0.82 on an H100. We measure 1.50 h on an RTX 5090 under a stricter criterion. The speed-ups compare InstantTrack with our SuperMimic on the same machine, not with the paper's numbers.

Why compare with SuperMimic + EMA?

A Polyak-averaged policy alone takes SuperMimic from 1.50 h to 0.55 h. Any SuperMimic implementation can adopt it, so we treat SuperMimic + EMA as the fair baseline and quote 2.2× against it.

How is time measured?

Training wall-clock on an otherwise idle GPU. It includes torch.compile warm-up and checkpoint writing, and it excludes the offline evaluation of checkpoints. Checkpoints come every 3 minutes, so times are quantized to 0.05 h. GPU runs are not bit-reproducible: re-running one seed of one configuration moved it from 0.30 h to 0.34 h.

Where is InstantTrack worse?

With the contact reward, normalized return at 1.5 h is 0.877, against 0.880 for SuperMimic + EMA, and global root drift is larger. Feet that stick to the ground do not slide along where the reference itself slides, which is about 10.2 cm/s of slip from retargeting. Without the contact reward, InstantTrack is better on every metric we measure.

What is not covered?

Only the Unitree G1 in simulation, on LAFAN1's 40 clips. There are no evaluation-time pushes or randomization, no hardware experiment and no larger motion library. Plain SuperMimic has one seed; the other methods have three.

Get started

Train your own
in 15 minutes.

You need Linux, an NVIDIA GPU with CUDA 12.8 drivers and uv. The download script fetches the G1 retargets of LAFAN1.

Setup, presets and reproduction scripts in the README ›

git clone https://github.com/Huy-Quang-Dao/instantTrack.git
cd instantTrack
uv sync
tools/download_data.sh
uv run python tools/test_env.py

# InstantTrack, 0.75 h, then evaluate every checkpoint
scripts/train.sh instanttrack it_s0 --seed 0 --max_hours 0.75

# the fair baseline
scripts/train.sh supermimic_ema sm_ema_s0 --seed 0 --max_hours 0.75
