Speed

Same data. Same GPU.
A fraction of the time.

The policy running on our robot took most of a day to train. InstantGMT reaches the same tracking quality in hours, with the same motion library, network and evaluation.

Method

One loop. Nothing wasted.

InstantGMT keeps SuperMimic's loop: a learned world model and analytic policy gradients through it. It changes how the loop runs, not what it learns.

01

An averaged policy

The deployed policy is an exponential moving average of the trained one. Less noise between checkpoints, earlier good checkpoints.

effect: —
02

Muon

Orthogonalized updates for the hidden layers of the world model and the policy. Same learning-rate schedule.

effect: —
03

No host syncs

Guards, metrics and timers stay on the GPU, so the CPU never waits for it inside an iteration.

effect: —
04

One graph per step

The parallel-ankle closure no longer breaks the compiled world-model step. Each update replays as a CUDA graph.

effect: —
05

Read each motion once

The reference windows of a rollout overlap. One gather per rollout from the host-side library replaces ten.

effect: —
06

The same policy

Network, observations, actions and rewards are unchanged. The checkpoint drops into the existing robot controller.

effect: drop-in

Questions? Answers.

What is general motion tracking?

One policy that follows any reference motion, not a fixed set of clips. Here the reference streams live from a VR headset.

Does InstantGMT change what the policy learns?

No. Rewards, observations, network and robot interface are those of the deployed policy. InstantGMT changes the optimizer and how the training loop runs.

Is the comparison fair?

Same motion library, same GPU model, same evaluation. Details with the paper.

Has it run on hardware?

Sim-to-sim with the robot's controller first; real-robot results with the paper.
